# Query集合の索引保持

Queryの所属集合と削除待ち集合は、世代を含む完全なEntity番号をkeyとして扱う。slotへ切り詰めず、削除待ちの旧世代と新世代が同時に存在しても混同しない。通知・追跡Query・削除確定の境界は維持する。

SparseSetは新しいkeyの追加を計数し、未整理key数が生存集合の2倍かつ1024を超える場合に現在集合から疎索引を再構築する。同じkeyの再利用や通常のremoveでは再構築しない。clearは索引を解放する。sortは現在の有効範囲だけを整列して索引を作る。denseのcapacityは過去の最大集合サイズに応じて残りうるが、生成・削除回数そのものに比例した索引を保持し続けない。

削除ごとのdeleteは通常の除去経路を大幅に遅くするため採用しない。小集合の閾値1024は再構築の反復を抑える固定上限であり、Entity数の上限ではない。再構築は追加時に同期して行い、transactionや遅延したゲーム状態の書戻しを導入しない。

Queryが再実行されるまでの削除queueや、利用者が保持した過去のQuery結果は別の所有物である。疎索引の整理によってそれらの公開契約を変えない。
