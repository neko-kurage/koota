# Entityの有効状態とQuery参加

Entity自身のenabledと外部の参加条件を合成して実効activeを決める。外部条件は自身の設定を上書きしない。休止は値やTraitを除去せず、通常Queryから除外する。IncludeDisabledを明示した集合はdisabledな個体も含む。

Query結果は取得時の集合のsnapshot。readEach/updateEachは通常Queryのcallback直前にdisabled状態を確認する。元々含まれる個体がその番までに再enableされていれば呼ぶ。新たな個体を追加せず、呼出し済みの個体を再実行しない。IncludeDisabledの結果では活動状態による除外を行わない。生の配列操作へこの検査を暗黙に追加しない。

活動変更では内部Query・Relation索引を整えてから利用側へ集合通知を配送する。例外で後続の利用側通知を止め、既に変わった状態を巻き戻さない。休止だけでTrait値の変更通知を発生させない。削除・世代再利用で旧個体の設定を次の個体へ引き継がない。

Prefab階層、resource所有、callbackの使用中管理、自動更新停止は利用側の責務。KootaのQuery走査自体はresourceの使用期間を開始しない。
