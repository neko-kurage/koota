# Queryの疎索引保持の修正

500体の生成・削除を10万回反復すると、QueryのSparseSetが削除済みの世代番号を保持し、Koota単体のGC後heapが約4〜5MBから17MBへ増える。通常Queryと購読用Queryで同じ問題がある。

単純delete案は保持を解消するが、5,000体のTrait除去が0.029msから0.274msへ悪化したため不採用。新規keyの蓄積が生存数の2倍または1024を超えたときだけ再構築する案を検証中。削除時の経路と世代を含む完全なkeyは維持する。clearで全keyを解放し、sortで除去済みtailを集合へ戻さない。

source検証・配布物のbuild・CPU比較・利用側での受入確認が残る。作業状態は[Audit](../../../audit.md)を参照。
