# Entityの一括生成

以下は2026-11-02に始めた先行設計の本文です。当時の合意・実装状態と測定条件を保持しています。後続の変更と本番接続は末尾の「本番接続と検証（2026-11-04）」に追記しました。

合意状態：試作・速度検証を合意。実装状態：隔離worktreeで試作・正式比較まで確認。本番採用は未決定。本番依存は未変更。

1万Entity・2数値Traitの生成を1ms以内へ近づけます。`spawnBatch(world, count, ...traits)`は同じ初期構成を持つEntityを返す試作の入口です。初期値が異なるPrefabへの接続と、nekoのScope・Activityの変更は今回の範囲へ含めません。

この資料はKoota単体の先行試作を扱います。その後の生成時gate・所有接続と公開生成全体の比較は、[nekoの作業資料](../../../../../../neko-threejs/docs/Draft/Runtime/entity-creation/README.md)へ引き継いでいます。

## 初期値と通知

`spawnBatch(world, count, ...traits)`の先行試作の最終候補は、同じSoAの初期値・登録先・世代maskを一回準備してから、Entityを生成順に初期化します。QueryがあればTraitごとの既存遷移を使い、Queryがなければ世代単位でmaskを合成します。Entityの所属Setは独立したままです。

Query／Trait通知、factory、Relation、設定値、公開storeなどを扱う場合は、通常生成を反復します。`Position({ x: 1 })`のような設定値付きの呼出しも、この試作では高速化対象ではありません。値が個別に異なるPrefabへの接続は次の設計です。

通常の生成・追加・削除・保存の生成コード本文は基準と一致させています。最終候補は1万件が約1.26〜1.28msで、1ms目標は未達です。[測定記録](../../../Performance/Entity/batch-spawn/2026-11-02_batch-spawn.md)に採否・制限・復元手順を残しました。Entity管理の保持形式を見直す場合は、追加・除去・破棄も共通の表現として扱う必要があります。

## 生成準備の失効

Worldへrevisionを1つ追加する後続の隔離候補では、Query登録・Trait購読・store公開・reset時に保存準備を再確認しました。構成全体へ適用しても判定幅を超える高速化は得られず、この追加状態案は採用しません。reset後に古いstore・gateを使う欠陥は、instanceの同一性による8行の最小修正へ分離しました。この修正は生成・通常生成／Query／Relation・更新の比較で同等、p95停止なしです。独立復元したcore 199／配布物234テスト・型・packも成功し、最終隔離候補に残しました。[変更別の結果と復元](../../../../../../neko-threejs/docs/History/Runtime/entity-creation/2026-11-03_preparation-revision.md)を参照してください。

## 本番接続と検証（2026-11-04）

先行試作後、生成時の無効状態、個別初期値、所有接続と通知順、Entityの所属保存を見直し、本番へ接続しました。現行の公開入口は`spawnBatch(world, count, options)`です。全件の保存と所有接続を終えてから通知する構成と、Relationなどを個体ごとに保存・通知する構成を区別します。APIと現行順序は[一括生成](../../../../API/spawn-batch.md)、[有効状態](../../../../Architecture/Structure/Entity/01-activation.md)、[削除](../../../../Architecture/Structure/Entity/02-destruction.md)へ反映しました。

nekoはKootaの固定配布物`0.6.6-neko.11`へ接続しました。Core 212・collections 27・React 37・配布物247テスト、型・上流build・packを通過し、lintはerror 0（既存warningあり）です。採否、変更ごとの性能、source・測定版の復元と利用側の確認は[nekoの共通化記録](../../../../../../neko-threejs/docs/History/Runtime/contract-pruning/2026-11-04_common-lifetime.md)を参照します。

2026-11-05の接続版`0.6.6-neko.12`では、Entityの一括削除とTrait変更履歴の行の解放を追加しました。対応するsourceは `16974bb8574b31572d39d778fba3782e27565d01` です。固定Node 24.4.0とpnpm 10.32.0で型検査・source 278件・配布用247件のテスト、build・packが通り、再ビルドしたdistは採用済みtgz内のdistと全ファイルが一致しました。[本番接続の測定と復元](../../../../../../neko-threejs/docs/History/Runtime/deferred-lifetime/2026-11-04_deferred-lifetime.md#本番の配布物で確認する)に比較条件を記録しています。

先行試作の約1.26〜1.28msという結果は当時のfixtureとNodeによるものです。後続のneko全体の生成結果は入力・toolchain・計時区間が異なるため、Koota単体の1ms達成の根拠へ置き換えません。
